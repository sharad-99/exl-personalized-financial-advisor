# EXL Personalized Financial Advisor

An in-app **financial wellness coach** for bank customers. It turns a customer's income, spending,
savings, obligations and goals into **explainable, personalised insights** and next-best actions.
Built for the EXL Live Project (Banking & Wealth Management — Personalized Financial Advisor).

> **All data is synthetic.** Every person, account, transaction and balance is generated by a
> reproducible generator. Nothing here is real bank data, and nothing here is regulated
> investment advice.

## What it does

| Area | Highlights |
|---|---|
| Analytics | Income, expenses, net observed cash flow, savings rate, category spend, recurring charges, month-over-month change, emergency-fund coverage, goal progress, upcoming obligations, data freshness and confidence. Exact decimal maths; transfers, refunds, reversals and duplicate imports are never double counted. |
| Money coach | 8 deterministic, versioned rules. Every recommendation stores its inputs, calculations, assumptions, priority reason, confidence and rule version. No LLMs, no loans, no securities, no transactions. Missing or stale data triggers a request for data instead of a guess. |
| Product | Dashboard, financial profile, money coach (accept / dismiss / "something's wrong"), goals with safe monthly plans, recommendation history, settings with consent controls. Customer and read-only advisor views. |
| Security | Supabase Auth (or a development-only local login), server-side authorisation on every customer-scoped request, httpOnly session cookies, backend-for-frontend proxy, RLS + least-privilege DB role, rate limits, audit log. |

## Architecture

```
Browser ──► Next.js 16 (Vercel)            ──► FastAPI (Python host)     ──► PostgreSQL (Supabase)
            pages + /api/backend proxy           auth, authorisation,          tables, RLS, audit
            (httpOnly session cookie)            analytics, rules engine       (SQLite for local demo)
```

Details: [docs/architecture.md](docs/architecture.md).

```
backend/     FastAPI app (app/), tests (unit, integration, security), pinned requirements
frontend/    Next.js App Router + TypeScript + Tailwind + Recharts, Playwright e2e
supabase/    SQL migrations (schema, RLS, reference data), config, seed hook
scripts/     generate / validate synthetic data, run all quality checks
docs/        architecture, database, API, engine, data, security, testing, deployment, PRD
```

## Quick start (macOS)

Requirements: **Python 3.12+** (developed on 3.14), **Node.js 20.9+** (developed on 24), npm, git.
Docker is optional (only for a local PostgreSQL); the default local database is SQLite.

```bash
make setup
```

```bash
make seed
```

Then, in two terminals:

```bash
make api
```

```bash
make web
```

Open http://localhost:3000 and sign in with a synthetic demo account:

- Customer view: `customer01@demo.exl.test` … `customer60@demo.exl.test`
- Advisor view (read-only, all customers): `advisor@demo.exl.test`
- Password: the `LOCAL_DEMO_PASSWORD` value that `make setup` generated in `backend/.env`

API docs: http://localhost:8000/docs · Health: http://localhost:8000/health

`make setup` creates `backend/.venv`, installs pinned dependencies, runs `npm ci`, and creates
`backend/.env` and `frontend/.env.local` from the `.env.example` templates with freshly generated
local secrets. It never overwrites existing env files.

### Without make

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
```

```bash
cp backend/.env.example backend/.env
```

Edit `backend/.env`: set `LOCAL_JWT_SECRET` (32+ random characters) and `LOCAL_DEMO_PASSWORD`, and
clear `SUPABASE_URL`. Then seed and run:

```bash
cd backend && .venv/bin/python -m app.synthetic_data.seed --seed 42 --reset && .venv/bin/uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend && npm ci && cp .env.example .env.local && npm run dev
```

### Local PostgreSQL instead of SQLite (optional)

```bash
cp .env.example .env
```

Set `POSTGRES_PASSWORD` in `.env`, then start the database:

```bash
make db-up
```

Set `DATABASE_URL=postgresql://exl_dev:<password>@localhost:54329/exl_advisor` in `backend/.env`, then:

```bash
make migrate && make seed
```

## Environment variables

| Service | Variable | Purpose |
|---|---|---|
| backend | `ENVIRONMENT` | `development`, `test` or `production` (production enforces Supabase auth, PostgreSQL, https CORS) |
| backend | `DATABASE_URL` | SQLite file (demo) or PostgreSQL / Supabase pooled connection string |
| backend | `AUTH_MODE` | `local` (dev-only demo login) or `supabase` |
| backend | `LOCAL_JWT_SECRET`, `LOCAL_DEMO_PASSWORD` | Local mode only; never used in production |
| backend | `SUPABASE_URL`, `SUPABASE_JWT_SECRET` | Supabase token verification (JWKS by default; HS256 secret only for legacy projects) |
| backend | `CORS_ALLOWED_ORIGINS` | Comma-separated explicit origins (wildcards rejected) |
| frontend | `API_BASE_URL` | Server-side only URL of the FastAPI backend |
| frontend | `AUTH_MODE` | Must match the backend |
| frontend | `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase mode only (public by design; protected by RLS) |

Real `.env` files are git-ignored. Only `.env.example` placeholders are committed.

## Commands

| Command | What it does |
|---|---|
| `make seed` | Load reproducible synthetic data (`SEED=42` by default) |
| `make data` | Export the dataset to `data/generated/` as CSV + JSON |
| `make validate` | Validate the dataset (FKs, balances, transfers, history length, identifiers) |
| `make test` | Backend unit, integration and security tests |
| `make test-postgres` | PostgreSQL tests (`TEST_DATABASE_URL`; drops that database's public schema) |
| `make lint` / `make typecheck` / `make build` | Static checks and the production build |
| `make e2e` | Playwright journey (backend + frontend running, `E2E_PASSWORD` set) |
| `make check` | All quality gates with a summary |

## Troubleshooting

| Symptom | Fix |
|---|---|
| Backend exits with `LOCAL_JWT_SECRET must be set` | Run `make env`, or set the value in `backend/.env` |
| Login says the service is unavailable | Start the backend (`make api`) and check `API_BASE_URL` in `frontend/.env.local` |
| "Invalid email or password" | Use the `LOCAL_DEMO_PASSWORD` from `backend/.env`; restart the API after changing it |
| Dashboard empty / no customers | Run `make seed` |
| Data shows as stale | The seed date is "today" when seeded; re-run `make seed` to refresh dates |
| `429 Too many requests` | Rate limit reached; wait a minute |
| e2e journey finds no open advice | Re-seed (`make seed`): earlier runs dismissed the persona's recommendations |
| Port already in use | Stop the other process or change `--port` |
